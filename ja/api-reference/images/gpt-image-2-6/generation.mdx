<Note>
GPT-Image 2.6 には AIReiter 内で2つのモデル名があります：`gpt_image_2_6_flare` と `gpt_image_2_6_sunburst`。単独の `gpt_image_2_6` はありません。両モデルのパラメータは完全に同一です。

`output_format` は `png`（デフォルト）または `gif` を選択できます。本インターフェースでは `quality`、`output_n`、`background` は提供されておらず、SVGベクター画像やマスク / 囲み選択による部分編集もサポートしていません。
</Note>

## Body

<ParamField body="model" type="string" required>
  モデル名（以下のいずれかを選択）：

  * `"gpt_image_2_6_flare"` — Flare。生成速度が速く、下書きや一括生成に適しています
  * `"gpt_image_2_6_sunburst"` — Sunburst。ディテールを重視しており、人物・商品・レイアウトを維持したい編集に適しています

  2つのモデルを比較する際は、プロンプト、参照画像、アスペクト比、解像度を同一に保ってください。
</ParamField>

<ParamField body="params" type="object" required>
  モデルパラメータオブジェクト

  <Expandable title="params オブジェクトのプロパティ">
    <ParamField body="prompt" type="string" required>
      画像生成のテキスト説明

      * 中国語および英語に対応しています。詳細な説明を推奨します
      * 画像編集時は、変更する箇所と維持すべき箇所を明確に記述してください
      * 透過背景が必要な場合は、プロンプト内で直接指定してください（例："transparent background"）。透過されるかどうかはモデルによって決定されます
      * 送信前にプラットフォームのNGワードおよび安全性審査が行われ、違反コンテンツに該当する場合は直接エラーが返されます
    </ParamField>

    <ParamField body="output_format" type="string" default="png">
      出力フォーマット。デフォルトは `png`

      * `png` - 静止画
      * `gif` - ループアニメーション。`frame_count`、`frame_duration_ms` と組み合わせて使用します

      <Warning>
        `gif` の場合、`image_url` 参照画像はサポートされません（指定するとタスクが失敗します）。また `resolution` は使用されず、`aspect_ratio` は `auto`、`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3` のみサポートされます。その他の比率を指定すると 400 が返されます。
      </Warning>
    </ParamField>

    <ParamField body="image_url" type="string[]">
      参照画像の配列。指定すると画像から画像生成（Image-to-Image）/ 編集モードになります（`output_format` が `png` の場合のみ利用可能）

      * 最大 10 枚の参照画像
      * 指定しない場合はテキストから画像生成（Text-to-Image）になります
      * 以下の2つのフォーマットに対応しています：
        1. 公開アクセス可能な URL
        2. Base64 エンコード形式
           * 完全な Data URI 形式を使用する必要があります：`data:image/{格式};base64,{base64数据}`
           * 対応画像フォーマット：jpeg、png、webp
           * 例：`data:image/jpeg;base64,/9j/4AAQSkZJRgABAQEAYABg...`
           * ⚠️ 注意：プレフィックス部分 `data:image/jpeg;base64,` を必ず含める必要があります
    </ParamField>

    <ParamField body="aspect_ratio" type="string" default="auto">
      画像生成のアスペクト比。デフォルトは `auto`

      以下の値をサポートしています：

      * `auto` - 最適な比率を自動選択
      * `1:1` - 正方形
      * `16:9` / `9:16` - ワイドスクリーン（横 / 縦）
      * `4:3` / `3:4` - スタンダード（横 / 縦）
      * `3:2` / `2:3` - クラシック（横 / 縦）
      * `5:4` / `4:5` - セミスクエア（横 / 縦）
      * `21:9` - ウルトラワイド（横）

      <Warning>
        比率文字列または `auto` のみサポートしています。ピクセルサイズ（`1024x1024` など）を指定すると直接エラーになります。正確なピクセル数を指定したい場合は `size` を使用してください。
      </Warning>
    </ParamField>

    <ParamField body="resolution" type="string" default="1K">
      解像度レベル。デフォルトは `1K`

      * `1K` - 約 1024 基準
      * `2K` - 約 2048 基準
      * `4K` - 約 3840 基準

      <Warning>
        `size` を指定する場合は、`resolution` / `aspect_ratio` を同時に指定しないでください。同時に指定すると 400 が返されます。
      </Warning>
    </ParamField>

    <ParamField body="frame_count" type="integer" default="9">
      GIF フレーム数。`output_format` が `gif` の場合のみ有効。デフォルトは `9`

      * 有効範囲は `2` ~ `9`。範囲外の場合は 400 が返されます
    </ParamField>

    <ParamField body="frame_duration_ms" type="integer" default="200">
      GIF の1フレームあたりの表示時間（ミリ秒）。`output_format` が `gif` の場合のみ有効。デフォルトは `200`

      * 有効範囲は `100` ~ `500`（10ミリ秒単位で丸められます）。範囲外の場合は 400 が返されます
      * 例：9フレーム × 200ミリ秒の場合、1ループは 1.8秒になります
    </ParamField>

    <ParamField body="size" type="string">
      カスタムピクセルサイズ（APIのみ。`aspect_ratio` / `resolution` と**排他**）

      形式は `幅x高さ` です（例：`2048x1536`、`3840x2160`）。

      **使用制限：**

      * 形式は `^\d+x\d+$` である必要があります
      * 幅・高さはともに 16 の倍数である必要があります
      * 各辺は最大 3840 まで
      * 長辺 / 短辺の比率は 3:1 以下
      * 総ピクセル数（幅 × 高さ）は **655,360 ~ 8,294,400** の範囲内
      * `aspect_ratio`、`resolution` と排他です。同時に指定すると 400 が返されます
      * `gif` の場合、比率に応じて最も近い GIF フレームサイズに変換されます（下部の GIF フレームサイズ表を参照）
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="out_task_id" type="string" required>
  リクエスト元タスク ID

  ユーザー定義のタスク識別子（必須）。結果を照会する際は、同じ値を使用して `POST /api/openapi/query` を呼び出してください。
</ParamField>

## サイズ × 解像度マッピング表

`aspect_ratio × resolution` → 実際のピクセル数（`auto` はモデルが自動的に選択するため、表には含まれません）：

| aspect\_ratio | `1K`      | `2K`      | `4K`      |
| ------------- | --------- | --------- | --------- |
| `1:1`         | 1024×1024 | 2048×2048 | 2880×2880 |
| `3:2`         | 1248×832  | 2496×1664 | 3504×2336 |
| `2:3`         | 832×1248  | 1664×2496 | 2336×3504 |
| `4:3`         | 1152×864  | 2304×1728 | 3264×2448 |
| `3:4`         | 864×1152  | 1728×2304 | 2448×3264 |
| `5:4`         | 1120×896  | 2240×1792 | 3200×2560 |
| `4:5`         | 896×1120  | 1792×2240 | 2560×3200 |
| `16:9`        | 1280×720  | 2560×1440 | 3840×2160 |
| `9:16`        | 720×1280  | 1440×2560 | 2160×3840 |
| `21:9`        | 1456×624  | 3024×1296 | 3696×1584 |

> `2:1`、`1:2`、`9:21` はサポートされておらず、指定すると 400 が返されます。表以外の比率が必要な場合は `size` を使用してください。

## GIF 帧尺寸

`output_format` が `gif` の場合、各フレームのサイズは `aspect_ratio` によって決定されます（`auto` は `1:1`）：

| aspect\_ratio | 各フレームのサイズ |
| ------------- | -------- |
| `1:1`         | 896×896  |
| `16:9`        | 1088×608 |
| `9:16`        | 608×1088 |
| `4:3`         | 960×720  |
| `3:4`         | 720×960  |
| `3:2`         | 1008×672 |
| `2:3`         | 672×1008 |

## Query Task

GPT-Image 2.6は非同期画像生成モデルです。タスク送信後、`out_task_id`を使用してタスクステータスを照会してください。[タスクステータスの取得](/ja/api-reference/tasks/status)も参照してください。

<ParamField body="out_task_id" type="string" required>
  タスク送信時に渡されたリクエスター側のタスクID。
</ParamField>

```bash
curl --request POST \
  --url https://aireiter.com/api/openapi/query \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "out_task_id": "my_task_123456"
  }'
```

照会が成功して完了すると、レスポンス内の `output` 配列に生成された画像（PNGまたはGIF）が含まれます。

実測値として、1K画像1枚は約25〜45秒、GIFは約25〜70秒で完了し、Sunburstは通常Flareよりやや遅くなります。解像度が高いほど、また参照画像が多いほど処理時間が長くなりますので、重複して送信せず、継続的にポーリングを行ってください。

## 使用说明

* `prompt` のみを渡した場合はテキストからの画像生成となり、`image_url` を渡した場合は参照画像に基づく編集処理が行われ、プロンプトで指定されていない部分は可能な限り維持されます。
* 1回のリクエストにつき1枚の画像のみが返されます。複数枚が必要な場合は個別にリクエストしてください。
* デフォルトでは PNG を出力します。`output_format: "gif"` を渡すとループ GIF アニメーションを出力します。
* GIF は `prompt` のみに基づいて生成されます。プロンプトには主体、動作、ループ方法（例: 「手を振った後に元の姿勢に戻る」など）を明確に記述してください。動作がシンプルなほど、フレーム間の連続性が高くなります。
* 4K 設定は大サイズでの納品が必要なシーンに適しています。ディテールが重視される写実的な画像の場合は、まず 1K / 2K で構図を確認した上で 4K を出力することをお勧めします。
